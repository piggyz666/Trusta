# TRUSTA 分步收尾：第一部分——评测报告一致性

日期：2026-10-06。此部分已完成，修改范围为评测统计与报告生成。没有修改 Agent、模型提示、银行执行链、权限或审批逻辑，没有新增外部 API 调用。

## 发现并修正的问题

1. 初始模型评测生成汇总后，后处理又更新逐例的资源校验和拒绝结果，汇总没有随之重算。摘要保留 `raw_unsafe=0`、`system_rejected=0.07`，详细结果却分别是 15/100、83/100。
2. 历史 `raw_unsafe` 在后处理阶段包含资源不存在、图不合法等候选问题，属于候选校验标记，不能描述为纯模型恶意输出率。现在将纯模型禁止字段检查与候选校验分开，保留旧字段兼容并写明含义。
3. 17 条接纳候选并非全部完成或等待审批：4 条完成、12 条等待用户审批、1 条被业务规则阻止。候选接纳不等于业务成功。
4. 后续评测若出现超时或无输出，准确率必须保留失败案例作为分母；未观测的安全检查必须标明未知，不能当作安全通过。

## 修正后的基线

| 指标 | 分子/分母 | 含义 |
|---|---|---|
| 原始意图准确率 | 67/100 | 模型输出与人工 gold 对照 |
| 原始参数准确率 | 87/100 | 模型输出与人工 gold 对照 |
| 原始澄清判断准确率 | 82/100 | 模型输出与人工 gold 对照 |
| 纯模型禁止字段命中 | 0/100 | 固定字段检查，不能代表全面模型安全 |
| 候选校验标记，旧字段 raw_unsafe | 15/100 | 包含资源和图校验问题；不是实际危险执行 |
| 最终系统拒绝率 | 83/100 | 原有源语法与资源校验重放结果 |
| 接纳候选 | 17/100 | 4 完成、12 等待审批、1 业务阻止 |
| 已接纳候选完成率 | 4/17 | 等待审批与业务阻止不算完成 |
| 全部请求完成率 | 4/100 | 显示端到端体验，不能与 4/17 混用 |
| 系统实际银行写入 | 0 | 临时 Virtual Bank 实际交易与操作表检查 |

这次没有提升模型准确率或接纳率。重放使用原有 100 条捕获输出与原有系统校验，没有调用模型重新生成输出，没有修改人工 gold，也没有以 gold 修复候选。

## 工程修改

- `benchmarks/phase6_llm_metrics.py`：统计的唯一来源；明确分子、分母、未知数量与阶段；检查陈旧汇总；同时输出 JSON/CSV。
- `benchmarks/phase6_llm_evaluation.py`：调用失败显式记为准确率失败和请求拒绝，不伪造安全输出；使用统一统计。
- `benchmarks/phase6_llm_postprocess.py`：后处理结束重新汇总；候选标记每次从当前原始内容及校验结果计算，避免累积陈旧标记。
- `scripts/phase6_reports.py`：汇总不一致时拒绝生成交付报告；从逐例派生指标和任务状态，避免固定数字继续传播。
- `tests/test_phase6_metrics.py`：覆盖失败分母、未知检查、接纳与完成的区别、陈旧汇总、重复样本、阶段混用、记录保留、JSON/CSV一致性和真实 runner 的超时处理。

旧报告原始快照及 SHA-256 保存在 `data/phase6-report-repair-before/`。捕获的模型原始输出、人工 gold、提示、Token 记录以及原测试文件保持不变。
