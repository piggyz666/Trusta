# 银行安全审查说明（简版）

本文供银行在接入前做安全审查时参考。内容包括：TRUSTA 拿到哪些数据、存在哪里、发给谁，凭据怎么保存，谁能做什么，出了问题如何追溯。

文中每一项都对应仓库里的代码或测试，括号里注明位置。

## 1. 数据流向

```
客户（网页 / 手机 / 飞书） ──► TRUSTA ──► 银行接口（适配器）
                                 │
                                 ├──► 大模型（只用于理解客户的话，可换成银行内部部署的模型）
                                 └──► 公开行情接口（金价、汇率；不带任何客户数据）
```

| 数据 | 从哪里来 | 发给大模型吗 | TRUSTA 本地是否保存 |
|---|---|---|---|
| 账户余额、交易流水 | 银行接口，按需读取 | **不发** | 不单独保存；办理业务时，签名动作的前置 / 后置状态里带有当时的余额，随审计记录保存 |
| 账户、卡片、收款人、订阅等资源的编号与名称 | 银行接口 | 发编号和显示名，让模型能指认"哪张卡""给谁转"。收款人只发姓名和备注名，不发手机号；订阅会带每月金额，心愿金会带余额 | 不保存 |
| 入账的付款人、备注（他人填写） | 银行流水 | **不发**；疑似指令的文字只保存哈希，界面上只显示占位符 | 只保存被隔离文字的哈希 |
| 客户对话 | 客户输入 | 发（先经过提示注入与诈骗话术检测） | 保存，24 小时后会话失效 |
| 客户在 TRUSTA 里的设置（重要日期、活动计划、联动规则、卡面昵称） | 客户输入 | 不发 | 保存 |
| 授权、回执、审计记录 | TRUSTA 生成 | 不发 | 保存（哈希链） |

依据：
- 发给大模型的资源目录：`backend/chat/llm.py` 中的 `build_system_prompt`，目录里不含余额。
- 不可信文字的隔离：`backend/banking/sandbox_feed.py`、`backend/banking/transaction_feed.py`。

## 2. 凭据与部署

- **银行凭据**：放在环境变量或单独的密钥文件里，配置文件只记录路径和变量名。`config/bank.*.local.toml`、`.env`、`data/` 都已被 git 忽略。密钥文件和数据库目录启动时会收紧为仅本人可读（`backend/security/local_files.py`）。
- **访问范围**：默认只监听本机 127.0.0.1。开启局域网模式后，手机需要一次性配对码（6 位、5 分钟有效、单次使用、限制错误次数），每台设备单独发令牌，可以吊销，30 天过期（`backend/access.py`）。
- **大模型**：可以接任何兼容 OpenAI 接口的模型。银行可以换成内部部署的模型，不需要改代码，也可以完全不接模型，只用规则引擎。

## 3. 谁能动钱

- **AI 不能授权。** 模型只能提出操作，每一笔资金操作都要客户在确认卡上本人点击。聊天里说"确认"不会执行任何操作。
- **强验证。** 大额、当日累计超限、短时间内多笔、新收款人大额转账、外币，都要求动态口令或短信验证（`backend/security/banking_controls.py`）。
- **反诈冷静期。** 客户可以一键暂停 24 小时的对外转账。冷静期内只能由银行安全人员核实身份后解除。
- **分权。** 六个智能体各有一份权限清单，读和写分开，提出操作的智能体不能执行（`backend/security/registry.py`）。智能体之间的消息逐条用 ECDSA P-256 签名，并做防重放检查。
- **银行侧的安全阀。** 外部银行默认关闭写入。写入还受三项限制：只允许白名单账户付款、只允许白名单收款人、有单笔上限（`ExternalBankSafeMode`）。
- **执行前核对。** 签名动作带着前置条件和幂等键。账户状态变化了，银行拒绝执行；同一幂等键只执行一次；结果不确定时不会自动重发。

## 4. 出了问题如何追溯

- **成功的依据。** 每笔操作都要先通过银行核验，才会生成回执。核验不一致的进入人工核对，不显示"成功"（`backend/verification.py`、`backend/receipts.py`）。
- **审计链。** 授权、执行、回执、功能开关变化、可疑文字隔离都写入哈希链审计日志，篡改任意一条都会被发现。审计链可以定期生成 Merkle 检查点（`backend/audit.py`、`backend/audit_trust/`）。
- **功能状态可证明。** 某一时刻开放了哪些功能，会以哈希写入每次请求的签名信息中。事后可以证明办理时某项功能是否开放（`backend/capabilities.py`）。

## 5. 不在本项目范围内

以下事项需要银行或运营方完成：
- 接入银行自己的客户登录和强验证体系（本项目演示版使用本地令牌和演示用动态口令）；
- 生产环境的服务器部署、数据库选型、备份与监控；
- 等级保护测评、个人信息保护影响评估、渗透测试，以及生成式 AI 服务和算法的备案。
