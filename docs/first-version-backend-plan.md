# TRUSTA 第一版后端实施顺序

2026-10-08。用户确认：先补后端安全缺口，再完善六场景，然后完成创新能力；UI、安装向导和产品形态延后。本文件是当前实施计划，历史 Phase 报告继续作为历史证据。

## 不变的边界

- 不新增 Agent。六个已有 Agent 只读、分析、提案。
- 金融操作继续通过 BankActionIR、Schema/Capability、Policy、Authorization、Execution Contract、Tool Gateway、Bank Adapter、Verification、Receipt/Audit。
- 模型输出、Memory、人工处理意见均不构成金融授权。
- 已知银行交易只查询；未知写结果不自动重发。人工接管不能覆盖银行事实或强制生成成功回执。
- 本轮使用隔离本地数据库测试；不重新授权或付款，不重启当前 Revolut 演示服务，不进行生产资金操作。

## A. 安全缺口

第一批新增 `backend/security/banking_controls.py`，在原 Policy/Authorization/Contract/Gateway 位置接入，未新增执行路径：

1. Competition 配置：人民币按用户、上海日期累计，<=1000元确认、>1000元强验证；其他币种始终要求强验证，不进行隐式外汇换算。
2. 执行前用 SQLite BEGIN IMMEDIATE 原子登记额度，所有来源账户共享同用户额度。登记包含动作 hash 与幂等键，重复同动作不重复登记。未知结果保守保留登记，当日不能自动释放。
3. 本地历史转账计入累计；外部累计范围是 TRUSTA 自身发起的已登记转账，不宣称覆盖银行其他渠道的全部活动。
4. TOTP 独立认证：随机160位密钥、加密存储、5分钟待绑定期限、6位/30秒、正负一个窗口、同一用户验证码计数器防重放。绑定必须确认，已绑定不能通过普通用户接口覆盖。
5. 强认证证明绑定用户、authorization_id、动作 hash、时间、授权期限，由本地安全密钥签封；执行合约检查该证明。不能用旧演示口令通过 competition 强认证。
6. 连续5次无效/重放验证码、连续3次银行写异常锁定用户金融操作；状态跨进程/重启持久化。成功验证清认证失败数、成功调用清执行失败数，成功事件不能自动解锁已有锁定。只读诊断保留。
7. 独立本地操作员凭据与理由解锁，审计记录；待核查案件登记/操作员备注不会改变任务金融状态、银行状态、授权或回执。

历史 Python Config 默认 legacy，保留原测试与原演示口令语义；`Config.local()` 默认 competition，可显式设置 `TRUSTA_SAFETY_PROFILE=legacy` 启动历史隔离演示。启用 competition 的数据库持久化签封标记，禁止随后静默降级。

补充完成：权威核验明确返回 AUTHORITATIVE_STATE_MISMATCH 时立即持久化金融锁；其他未知/超时/消费异常候选不等同于确定欺诈。绿色读取继续使用原只读能力检查，不申请金融确认。新六场景的自由口语泛化仍需另行独立评测，不用工程测试代替模型评测。

## B. 六场景后端

以已实现的后台和测试为基础，逐个扩展并验收，不把全部赛题示例误称为已完成：

1. 转账：现有姓名/手机号/备注、定时和本地 AA；完善审批升级、参与者恢复/撤回、同币种路由与异常状态。
2. 账单：现有分类/月度/异常；增加年度聚合、跨月证据及官方银行分类映射边界。
3. 理财：现有比较/推荐/风险/沙箱申赎；统一强认证、持仓与现金/账本核验，扩充多轮输入。
4. 卡片：现有冻结/解冻/限额/交易开关；补申请、挂失与不可逆终态。新增金融能力须显式迁移 Registry 承诺，不偷偷更改既有密钥绑定。
5. 订阅/代扣：现有检测/取消/停用；增加幂等续费提醒队列、到期处理及取消后提醒一致性。
6. 跨场景：现有 DAG、逐项审批、TIME worker、恢复；补受控事件触发和一个完整联动案例。事件只触发提案，不提供无限期资金授权。

本轮已完成年度聚合、卡片申请记录/挂失终态、续费提醒、受控事件及后台 worker；审批/账本/未知状态沿用并回归原闭环。实际覆盖、外部银行边界及六场景 Demo 见 [当前交付](first-version-backend-delivery.md)。不是六个场景中每个示例都已连接真实银行/商户。

## C. 创新能力

1. DID：明确 DID 方法、可解析身份与验证材料、与既有 Registry/能力承诺绑定、密钥/撤销语义及独立验证器。
2. 外部链：复用现有合约/RPC，完成 Sepolia 部署、提交和独立读回；需要独立测试钱包、RPC、gas、合约地址。银行链不等待上链，链上只存承诺。
3. ZKP：先固定一个实际隐私命题及权威数据签发边界，再实现真实证明生成/验证、public input 与任务/期限绑定、错误输入/重放/越权测试。预留接口与本地算法示例都不能冒充已完成可信闭环。

生产银行、真实卡网络/商户取消和真实投资交易是另行外部验收，当前不作为第一版后端基础实施的阻塞条件。
