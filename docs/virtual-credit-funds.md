# 信用账单、基金份额与统一待办

这是虚拟资金练习系统。沿用 TRUSTA 的签名授权、逐笔确认、风险校验与独立执行验证，不发卡、不买卖真实基金、不向商户付款。

## 信用账单 `/bank/credit-account`

每张站内借记卡绑定一个独立的虚拟信用账户，额度 20,000 元。登记测试消费增加欠款，不改变借记卡余额；次日入账、每月 5 日出账、25 日还款。日期以北京时间为准。

全额还款覆盖当前全部欠款，包括未出账消费；最低还款取已出账净消费的 10%（逐笔向上取整到分），减去已还金额，不结清其余欠款。本练习产品不计循环利息或逾期费，这不是实际银行信用卡条款。

退款必须对应本人原消费且不能超过可退金额，优先冲抵欠款、恢复额度。多余部分记为溢缴款，用户确认后才能退回绑定借记卡。信用消费、退款、现金还款使用不同的账本科目，避免消费时误扣现金、退款时重复增加现金。

## 基金 `/bank/funds`

内置两个明确标注的练习产品，净值固定：债券练习基金 1.0250，指数练习基金 1.2500 元/份。申购费用分别为 0.20%、0.50%，赎回费用为 0.10%、0.20%；这些是虚拟产品设定，不是行情或真实产品报价。

申购确认后从所选卡扣款，生成待确认订单；份额确认前可以全额撤单，撤单不收费。份额确认不重复扣款，确认时记录申购费用和持仓成本。已确认份额可赎回，资金回原卡，不支持超额赎回。份额保留四位小数，结算金额及费用舍去不足一分。本练习不模拟实际交易日 T+1。

所有基金操作都走现有风险和强验证流程。申购及确认份额需风险测评有效且满足产品等级；赎回保留退出通道。过期、重复请求、余额不足、状态已变、非本人资源均不能绕过校验。申购冻结在待确认订单中的本金也纳入资产总览。

## 统一待办 `/bank/todos`

汇总未来 30 天及已过日期的贷款/分期、信用账单、定期到期、黄金定投、基金份额确认、活动计划、已开启提醒的重要日期，以及交易工单进展。只读展示，不定时扣款。进入业务页面后仍须核对与确认。

## 助手

新增 `get_extended` 和 `propose_extension` 工具。对象来自当前用户资源目录；金额、份额、币种、存期、还款方式必须匹配用户原话。模型不能指定风险等级、虚构报价或提交授权。基金赎回支持四位小数。资料不完整时先追问，不猜测账户、对象或金额。

无模型的规则助手也可准备明确的指令，例如“存入100元定期存款，90天”“申购100元稳健债券练习基金”。有多张卡时需补充卡片；无关问题不处理。真实 DeepSeek 联调状态以 AGENT-HANDOFF.md 为准，脚本模型通过不代表云模型已经联调。

## 验证

`tests/test_advanced.py` 检查信用消费、全额/最低还款、退款冲抵、溢缴款、基金撤单/份额/赎回、资产汇总、归属、风险、过期状态和 HTTP 授权。

`tests/test_extension_agent.py` 检查原话与资源匹配、禁止注入授权、基金精度、明确确认后的存款入账及只读待办。

`scripts/online_advanced_smoke.py` 校验正式网址页面和资源、身份认证、确认前不执行及明确拒绝后账本不变。它不批准生产账户资金操作，也不请求付费模型。完整资金闭环在隔离数据库完成。
