# HTTP API

The web app, the terminal client and Feishu all work through the same local HTTP API, which you can use for your own interface too.

## Conventions

- Address: `http://127.0.0.1:8000`.
- Everything except `/health` and static pages needs `Authorization: Bearer <token>`. The token is printed at start-up and saved in `data/api.token` by default; paired phones use their own device tokens.
- The server checks `Host` and `Origin`; the customer identity is decided server-side and clients **cannot** send a `user_id`.
- POST bodies are `Content-Type: application/json`.
- Amounts are always **integer minor units** of the account currency (fen for CNY); there is no implicit currency conversion.

## Chat

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/chat/sessions` | Create a session |
| GET | `/api/chat/sessions/{sid}` | Read a session: messages, current plan, pending cards (for reconnecting) |
| POST | `/api/chat/sessions/{sid}/messages` | Send a message |
| POST | `/api/chat/sessions/{sid}/actions/{action_id}/decision` | Decide on a confirmation card |
| POST | `/api/chat/sessions/{sid}/actions/{action_id}/sms` | Send a simulated SMS code for a red card |
| POST | `/api/chat/sessions/{sid}/interrupt` | Interrupt the current plan |
| POST | `/api/chat/sessions/{sid}/close` | Close the session |

### Sending a message

```json
POST /api/chat/sessions/{sid}/messages
{
  "message_id": "m_01J…",
  "revision": 3,
  "text": "给我妈转两千，备注生活费"
}
```

- `message_id` is generated by the client (1–64 characters); retrying with the same ID returns the original result without reprocessing.
- `revision` is the version from the previous response; a mismatch returns `CHAT_STALE`.
- `Accept: text/event-stream` streams Server-Sent Events; `Accept: application/json` returns once the whole turn is done.

SSE events include `turn.started`, `guard.result`, `intent.recognized`, `plan.created` / `plan.updated`, `tool.started` / `tool.finished`, `message.delta`, `card`, `turn.completed` and `turn.failed`. Treat the full result in `turn.completed` as final.

### Deciding on a card

```json
POST /api/chat/sessions/{sid}/actions/{action_id}/decision
{
  "action_hash": "sha256:…",
  "approve": true,
  "verification": { "method": "SMS", "code": "123456" }
}
```

`action_hash` must match the card exactly; `verification` is only needed for red operations (`TOTP` or `SMS`).

## Tasks (lower level)

Underneath the chat layer is the task API, where every money action lands with its hash binding, expiry and anti-replay rules intact:

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/tasks` | Create a task, e.g. `{"text":"给张三转 2000 元"}` |
| GET | `/api/tasks` | Summary of the customer's tasks |
| GET | `/api/tasks/{id}` | Status, task graph, authorisation and evidence |
| POST | `/api/tasks/{id}/authorize` | Authorise: `{"action_hash":"…","approve":true}` |
| GET | `/api/balance` | Account balance |
| GET | `/api/transactions?account_id=…&month=YYYY-MM` | Transactions for an account and month |
| GET | `/api/audit` | Whether the audit chain is intact: `{"valid": true}` |
| GET | `/api/audit/proof` | Merkle inclusion proof for an audit record |

An HTTP success doesn't mean the money moved; always check the task status:

| Status | Meaning |
|---|---|
| `WAITING_USER` | Waiting for confirmation or missing details |
| `COMPLETED` | Settled, and the bank-side state was verified |
| `BLOCKED` | Stopped by a rule or safety gate |
| `CANCELLED` | Declined by the user |
| `FAILED` | Failed before execution or in the bank transaction |
| `MANUAL_REVIEW` | May have executed and needs a human check — **do not repeat the transfer** |

## Errors

| Status | Meaning |
|---|---|
| 400 | Input or safety validation failed |
| 403 | Identity, origin or ownership refused |
| 404 | Unknown endpoint |
| 500 | Unclassified error; refresh the original task's status instead of starting a new money operation |

There is no endpoint for clients to write to the bank directly, no execution endpoint for agents, and no automatic retry of money writes.

The full protocol is in `docs/chat-protocol-v1.md` and `docs/api.md` in the repository.
